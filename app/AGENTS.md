# 原生销售工作台开发规范

## 范围与工程基线

- 本文件适用于 `app/` 及其子目录。HBuilderX 打开本目录；仓库根目录的 `src/`、`android/`、`ios/` 属于旧 H5/Capacitor 工程，其技术约定不自动应用于本目录。
- 当前使用 uni-app x、UTS、UVue、Vue 3；页面为 `.uvue`，业务模块为 `.uts`。HBuilderX 基线为 **5.26.2026091802**，`manifest.json` 当前采用 **VDOM（`vapor: false`）**，目标为 Android、iOS、HarmonyOS。升级版本或切换渲染模式应作为明确的工程变更，并重新验证三端。
- 复用 `manifest.json` 中已有应用标识和 `pages.json` 中的导航配置。新增页面同步注册；不要在日常修改中重新生成 AppID 或更换包标识。
- Android 真机使用 `com.rigour.workbench` 自定义开发基座（HBuilderX 选择“自定义基座”，CLI 使用 `--playground custom`），不回退到 `io.dcloud.uniappx` 标准基座。开发版桌面名称为“销售工作台”，沿用公司橙色 R 标识；更换名称／图标需重新制作基座并同包覆盖安装，热更新不会替换桌面图标。保留旧基座数据，不自动卸载。详见 [应用标识](../docs/app-branding.md)。
- 开始前检查 Git 状态、任务交接及相关实现，保留其他任务的改动。安装技能不意味着迁移技术栈、引入组件库或清理旧工程。

## 技能与资料使用

- 编写、修改、审查或重构代码时使用 `karpathy-guidelines`，按任务规模落实最小改动和可验证目标。
- UTS/UVue 开发、接口类型调整、跨端兼容和编译排错使用 **`uniapp-x-skill`（Mr-xun）**。本次审查并安装的版本为 `409950265ebf288d0fa1e269abf2cc27ba7b3bf0`，默认安装位置为 `~/.codex/skills/uniapp-x-skill/`。读取入口 `SKILL.md` 后，按改动范围加载参考资料，不为文案修改加载全部语言规则。
- 区分三类依据：官方目标平台/版本支持是兼容性依据；本项目的版本、接口与目录选择是工程约定；社区技能中的保守写法是经验建议。用户当前指令优先，不能把经验建议扩展为无依据的全项目禁令。
- 技能内置规则是历史快照。遇到新 API、插件、样式、平台差异或编译诊断时，查当前 DCloud 官方文档及对应版本兼容表；不能用普通 TypeScript、浏览器 Vue/CSS 的经验推断原生支持。
- 界面设计使用已有 UI UX Pro Max，结合原生组件能力和当前页面上下文。查询其他库可使用 Context7；没有真实工具结果时不声称已查到文档。uni-agent 可辅助 HBuilderX 排错，其能力以实际连接和运行结果为准。
- 当前不引入第二套 uni-app x 技能、easycom MCP 或其他组件库。技能缺失时说明情况，继续依据项目代码和官方文档处理能够确认的部分，不自行批量安装工具。

## 现有目录与接口职责

| 位置 | 职责 |
|---|---|
| `App.uvue`、`main.uts` | 应用入口、全局生命周期 |
| `pages/`、`pages.json` | 页面展示、交互和导航注册 |
| `services/` | 按业务组织的接口、状态、原生采集与持久化模块；沿用已有结构，不为简单功能增加分层 |
| `styles/`、`static/` | 共享样式和静态资源；只抽取实际复用内容 |

- 业务请求复用 `services/api.uts` 和现有领域模块，通过 Gateway 访问后端；沿用 `services/config.uts` 的环境配置。认证、会话、Token 刷新与安全存储复用现有 `auth.uts`、`session.uts`、`secure-session.uts`，不在页面另写一套。
- 接口字段、分页、错误码、幂等键、版本号和权限以当前服务合同及真实响应为准。字段变更同时检查解析、类型、状态、模板和提交参数，不编造兼容字段，不用强制转换掩盖合同不一致。
- CRM 管理统一门店、联系人、数据范围、归属和掉落，并引用拜访规则快照核验门店拜访；Sales 管理销售工作台的拜访规则、定位门禁、照片与录音设置，并承接现场采集；Order 管理订单；Integration 承接高德等外部集成。App 提供销售作业界面，不复制后端状态机，不直接持有服务端集成密钥。
- 门店以 CRM `store_id` 为统一身份，POI 是外部关联标识，联系人和企微关系不作为新门店。客户管理接口不应要求先初始化 Sales；现场拜访再按接口要求校验销售身份、工作日和采集条件。
- 规则、查询与缓存按正式上线链路设计：修改前核对领域归属、接口、规则版本、库表/索引、业务更新路径和缓存失效条件；复用现有框架与共享服务，不为当前测试操作增加独立规则或页面缓存。拜访规则统一通过 `services/visit-policy.uts` 预加载和复用，服务端保留权限与适用范围校验；详见 [拜访入口与规则缓存合同](../docs/app-visit-entry-performance.md)。
- 展示、按钮与后端权限一致，但隐藏按钮不能代替后端鉴权。收到无权限、身份缺失、状态冲突或服务错误时明确提示，不伪装成空列表或成功。历史客户、临时打卡数据的迁移与切换由对应任务处理。

## 原生实现与界面

- API 和页面之间使用清晰的业务类型，显式处理可空字段。类型推导或模板转换出问题时，优先采用邻近已验证写法；按实际风险提取显示字段，不为每个简单表达式增加模型和转换层。
- 平台特有 API 使用条件编译或现有平台封装。定位、录音等采集优先复用 `services/location.uts`、`services/capture.uts` 及业务模块，避免在页面重复实现权限和生命周期处理。
- 原生定位当前为 WGS84。与 GCJ02 门店或地图数据交互时沿用已有标准化接口，传递真实坐标系，不只改标签，也不直接混算距离。区分定位请求/回调时间与设备采样时间；未知精度不填 0。
- 草稿、缓存、媒体与异步响应按账号/租户隔离；切换账号时不得串用上一个账号的数据。保留失败后的重试材料，依据实际文件保存及服务器回执分别展示“已保存”“已上传”“已提交”。
- 接续现有 `styles/theme.css` 和相关页面风格；布局、字号、间距按内容和屏幕适配，不固定无业务依据的高度、宽度、颜色或组件数量。用户提出新设计方向时可调整对应范围。
- UCSS 的属性、值、选择器和文本样式按实际目标平台验证。不能把 Web 预览效果当成 App 兼容证据，也不因为社区保守清单就全局禁用某个已受支持的样式。
- 覆盖加载、空态、错误、无权限、提交中与重试状态；交互检查软键盘、安全区、滚动、长文本及返回行为。真实接口失败时不静默切换为业务 Mock。

## 验证命令与证据

以下命令均在**仓库根目录**执行，脚本定义以根目录 `package.json` 为准：

| 命令 | 能验证的范围 |
|---|---|
| `pnpm app:v1:test` | 原生接口、认证、状态和 CRM 等自动化测试；包含测试替身，不等于真机验收 |
| `pnpm app:build:android` | 本地正式 APK 构建与既有签名校验，不走云打包 |
| `pnpm app:install:android` | 本地构建后校验手机原包签名，覆盖安装并保留数据 |
| `pnpm app:g0:test` | 原生采集状态测试；已包含在 `app:v1:test` 中，无变化时不用重复运行 |
| `pnpm app:g0:check:android` | Android 目标编译，不安装设备 |
| `pnpm app:g0:check:ios` | iOS 模拟器目标编译，不代表真机签名包验收 |
| `pnpm app:g0:check:harmony` | HarmonyOS 编译和本地 HAP 制作，不安装设备 |
| `pnpm app:g0:web` | Web 开发预览，不验证原生采集 |
| `pnpm app:g0:open` | 用现有 HBuilderX 打开原生工程 |
| `pnpm app:dev:android [deviceId]` | 启动 Android 自定义基座，并在调试进程存活期间自动维护业务 reverse |
| `pnpm app:dev:bridge [deviceId]` | 已有 HBuilderX 会话时单独维护同一手机的 26880/26881 转发 |
| `pnpm app:dev:test` | 开发通道转发恢复与设备选择回归 |

- 根据变更选择已有定向测试；跨端代码修改执行受影响平台的编译，公共原生代码变更验证三端。仅修改文档时检查内容、引用和命令即可，不启动应用或重复构建。根目录 `pnpm build` / `pnpm typecheck` 面向旧 H5，不能替代上述原生检查。
- Mr-xun 的 `scripts/audit.sh <目标文件或目录> official` 只读检查可用于改动范围。默认 `official` 检查覆盖有限，有告警也可能退出 0，必须读输出；不默认启用 `conservative-app`，不将其告警当成官方编译错误或直接作为 CI 阻断依据。
- HBuilderX CLI 通过已有 `scripts/app-g0.mjs` 调用；不要猜测 CLI 参数。确认编译成功日志及对应产物，不能只看进程退出码。`app-g0.mjs` 不执行云打包或发布。正式 Android 发布默认使用 `build-android-local.py`，详见 [本地正式打包](../docs/app-android-local-release.md)，不再默认提交云构建。
- Android 本地真机调试优先使用 `app:dev:android`；手动 HBuilderX 会话配合 `app:dev:bridge`，避免无线重连或调试工具重建连接后丢失业务转发。通道存活不代表服务正常或登录成功，仍需分别核查；不自行启动后端。
- 定位、相机、录音、锁屏/后台、断网重试、上传及账号切换按改动范围进行真实设备验证。浏览器、测试替身、模拟器通过，不等于 Android/iOS/鸿蒙真机均通过。
- 联调使用 DEV 和可识别测试数据，提交结果核对真实 API 与持久化事实。报告分别写清静态检查、编译、设备运行、接口/持久化验收及未验证项；本地通过不代表已发布。

## 工作边界与参考

- 沿用根目录通用规则：保留其他任务改动和已执行迁移；在用户日常目录开发；本地后端服务沿用现有 IDEA 运行项，需要启停时告知用户具体服务，不另起重复 JAR。
- 不在日志、Git、前端配置或普通本地存储中写入密码、Token、服务端 Secret。使用现有安全存储与服务端集成配置。
- 按当前任务授权执行提交、推送、数据迁移或发布；工具安装和原生开发本身不代表生产发布授权。
- 工程入口与构建说明见 [README.md](README.md)，原生能力与既有验证参考 [平台合同](../docs/app-g0-platform-contract.md)、[验证记录](../docs/app-g0-validation.md)、[认证接入](../docs/app-v1-auth-integration.md)。这些文档的历史完成状态不能代替本次实际证据；发生冲突时核对当前代码、服务合同与运行结果。

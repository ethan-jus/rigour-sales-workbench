# 外勤记录 V2 · 视觉与行程表达修订

2026-11-17。状态：修订评审稿，未替换原生 App。用户否定 V1 的页签、地图编号/GO文字、重复选中卡、左右切换和信息堆叠。此反馈优先于先前对编号、GO 的理解，本稿不以旧指令为现有设计辩护。继续使用 UI UX Pro Max 与既有品牌基线；本轮只新增设计文件，不改拜访、采集、轨迹计算及其他未提交改动。

## 页面只回答三个问题

1. 当天拜访了几次、停留多久、记录了多少路程？
2. 去了哪里？
3. 什么时间到达、离开，签到/签退的地址是什么？

顺序：日期 → 一行概览（里程/拜访次数/停留）→ 地图 → 按时间排序的记录。签到/签退时间地址统一在记录中；删除顶部两块打卡大卡、作业时段散行、地图下重复选中详情。

## 明确删除

- “拜访顺序 / 实际轨迹”切换，普通和全屏都删除。
- 地图上的“拜访 1–11”、GO 签到、END 签退等悬浮文字标签。
- 按打卡/门店位置直接连接的顺序虚线，尤其来回重复的两条直线。
- 地图下重复的事件详情、左右上一条/下一条按钮。
- 用里程数字、轨迹线或演示路径填补缺失定位的做法。

保留轻量位置符号：绿色圆点签到、橙色圆点拜访、红色方点签退；小图例在地图外。正式实施同时保留形状与文字图例，点击位置时再显示关联记录，不常驻大文字。同一门店多次拜访共用真实位置，时间记录保留每次发生事实。

## 路线与往返

- 地图默认只画服务端有效定位段；缺失期间断开。没有有效轨迹时只展示已知真实地点。
- 同一路段多次经过，不通过偏移坐标、重复粗线或文字堆叠表达次数。
- 全屏是同一份地图的放大，没有新增页签。通过“行程记录”时间列表直接选一段，不逐条左右翻找。
- 选中后：其他段淡化，当前时间段突出、显示方向箭头；下面只显示选中段的起止地点、时间和该段已记录里程。取消选中回全图。
- 列表“查看拜访”进入既有详情；“查看对应路段”选择到达本次拜访之前的路段。无可靠定位段时该动作应显示缺失原因，不渲染推测路径。
- 示例 11:52–14:10 是离开上一店至到达下一店的时间区间，不标成纯驾驶时长。
- 原生插件 Polyline 已声明 arrowLine，Android 适配器有对应传递；实施时仍需真机确认实际箭头方向、重复坐标、定位段切分、缩放以及密集点情况。

## 里程查证与展示口径

已查当前源代码：
- `SalesWorkAttendanceService.buildTrack()` 调用 `SalesTrackMetrics.calculate()`，返回 totalDistanceMeters、distanceAvailable、legs、gaps。已有计算，不是仅缺少一个前端求和。
- 只接收 ACCEPTED、带时间/坐标、精度大于0且不超过100米的点。不同采集会话、时间倒序、超出允许采样间隔、拒绝点或异常速度会断开。没有可用相邻点对则 available=false。
- 当前 App `parseFieldTrack()` 仅把 false 显示为“无法计算”；没有交代是定位不足、缺失还是其他情况。原顺序连线绕过了有效定位段，造成“地图画了线却没有里程”的理解矛盾。
- 此轮没有取得今天的原始定位点质量分布，不能断言是后台采集、上报、精度、时段间隔中的哪一个原因。实施前应在当前本人工作日数据上核对该问题，不通过放宽阈值或把门店直线相加掩盖原因。

展示三态：有完整有效记录显示“当日里程”；存在缺失显示“已记录里程”及简短缺失提示；没有有效段显示“—”和“暂无有效定位轨迹，里程未生成”。0 km 仅在确有有效点对且移动未达到计量门槛时展示，不代表缺数据。数字来自现有服务器事实，地点间距离不充当实际出行里程。完整性不能只依赖 available=true，需核对采集时段覆盖及已知 gaps。

全部示例数据（12.6 km、3次、80分钟、路线、门店）均为设计演示。12.6 km 示例分段为2.4+3.1+3.1+4.0；不是今日业务计算结果。全屏选段示例中的往返分别计入时段里程，线路视觉合并不改变累计值。

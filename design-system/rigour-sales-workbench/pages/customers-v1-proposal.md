# 客户页 V1 设计提案

2026-11-12。状态：设计评审，尚未修改 App 客户页面。沿用用户确认的登录、首页白底、石墨文字、品牌橙与紧凑间距。本稿中的门店、数量、日期均为示例数据。

## 页面职责

帮助业务员找到自己负责的门店、识别需要及时跟进的客户、从授权公海认领门店。以公司统一 `store_id` 为身份，不把联系人、企微账号或订货账户当成另一家门店。

当前原生 `customers.uvue` 以订货客户列表为主体，再通过一个大按钮跳转 CRM；`crm.uvue` 同时承载公私海列表、详情与联系人表单。建议客户 Tab 直接展示“我的客户／公海”，减少一层入口。此为待确认的信息结构方案，不自动合并两套数据。

## 列表布局

从上到下：系统安全区 → 客户标题与更多 → 我的客户／公海 → 搜索框与筛选 → 两个常用条件与结果数量 → 门店列表 → 固定五项底部导航。

- 标题“客户”23px，与首页一致；右上更多承接“订货客户”和有内容时的“购物草稿”。历史来源尚未全部匹配，旧订货客户查询不能在这次改版中消失。
- 默认“我的客户”；按权限显示页签，仅有一种权限时不留下无法使用的页签。
- 搜索占主要宽度，文案“搜索门店名称或地址”，支持键盘搜索、清空和约300ms防抖；不承诺当前接口不支持的联系人或手机号搜索。
- 我的客户常用条件：“全部阶段”“保护状态”；右侧为过滤后的“36家”。更多筛选通过搜索框旁的筛选图标进入底部面板。
- 公海常用条件：城市、区县；仅从授权地区选择。更多筛选保留合作情况、经营状态、门店类型等已有业务维度，不用一排彩色标签堆满屏幕。
- 不增加客户总量大卡片、宣传语、规则说明、CRM缩写、占位头像或整行大按钮。

## 我的客户行

以细分隔线组织列表，不给每家门店加阴影卡片。每行常规约92–100px，长店名或系统大字时自然增高，不以定高裁切信息。

1. 门店名称 + 本轮阶段。阶段短名“待首访／跟进中／维护中”，分别对应 FIRST_VISIT／FOLLOW_UP／COOPERATING。
2. 门店地址。常规一行，超长省略，在详情完整显示；保留区县信息帮助区分同名门店。
3. 最近拜访 + 明确标注的保护期限，例如“上次拜访11/10”“保护至11/17”；未拜访显示“尚未拜访”。最近拜访不冒充最近有效拜访。

临近24小时到期采用橙色文本；已经过期采用明确文字，不能只靠颜色。保护暂缓/保留状态单独展示，不给 hold 状态伪造倒计时。列表整行进入详情，不在每行叠加电话、导航、拜访、开单四个按钮。

## 公海行

- 仍以门店名、地址为主，辅助行展示经营状态和历史合作事实；“曾合作”不代表当前属于本人或已获得本轮长期保护。
- 右侧“认领”为唯一行内操作。使用低强调橙色描边，视觉按钮可紧凑，但实际点击区域至少48dp。
- 冷却中替换为不可点击状态，并显示可认领时间；其他禁止认领原因按后端结果展示。公海不展示私人联系人、手机号或员工企微备注。
- 点击门店正文查看公开详情；点击认领先用底部确认面板展示门店名和“认领后需在24小时内完成首访”，用户确认后再提交。这个确认只发生在取得新客户时，不在每次进入页面时重复提醒。
- 成功后移入我的客户并提供“去拜访”；冲突或权限变化时刷新状态，不先在本地假定认领成功。

## 详情与筛选流程

本轮效果图聚焦客户列表的两个页签。详情下一步沿相同风格展开：门店名/状态/完整地址 → 保护期限 → 联系人 → 拜访记录；开始/继续拜访为主要操作，经营状态维护、释放等低频操作收进更多。电话、导航按真实数据与权限提供，企微只显示已确认关系，不把手填微信线索显示为已建联。

筛选面板分组展示条件，底部“重置／查看结果”；阶段、保护状态、地区等均走服务端查询，不能只过滤已加载的20条。切换页签保留各自条件，修改条件回到第一页，返回详情保留列表位置。无结果提供“清空筛选”，接口失败提供“重试”，不把失败展示成0家。

## 当前能力与实现边界

| 内容 | 当前依据 | 实现时处理 |
| --- | --- | --- |
| 公海、我的客户、搜索、分页、认领 | `app/services/crm.uts` 与 CRM stores API 已有 | 复用，调整入口和布局 |
| 阶段、保护状态、地区等筛选 | 后端 StoreModels.Query、JdbcStorePoolStore 已有 | 原生请求补查询参数，不新增一套过滤口径 |
| 最近拜访、历史合作、经营状态、冷却、保护保留 | 后端 StoreModels.Row 已有，原生仅提取部分 | 扩充原生展示字段，不逐行额外发详情请求 |
| 公海详情 | 后端支持 view=PUBLIC，当前原生 crmDetail 固定 MINE | 带当前查看范围，按公海权限展示 |
| 到期优先、距离排序 | 当前列表按 store_id 游标分页，未见排序参数 | 本稿不画成已支持；需独立补服务端全量排序后再加入 |
| 地图、新增门店 | 后端已有相关能力，当前原生未提供对应完整页面 | 后续单独设计，遵循查重、入公海、认领流程，不画无效按钮 |
| 企微建联数据 | 当前未验证真实官方关系同步 | 不新增“已建联人数”或猜测的建联标签 |
| 客户订单/交易摘要 | 原订货客户与统一门店尚有过渡关联 | 本稿不按同名拼接或显示假汇总；保留原订货查询路径 |

## 视觉与验收

- 使用现有 `workbench-ui.css` 色值：白 #FFFFFF、正文 #252A31、辅助 #626970、橙 #C64C1C、浅灰 #F5F6F7、边界 #D6DBDF。
- 手机左右20px，与当前首页一致。标题23/32；店名16/24；地址和辅助13/20；控件14/22。选择状态通过字重/下划线/文字同时体现。
- 统一线性搜索、筛选、更多、箭头与底部导航图标。紧凑排版仍保留48dp可点击区；安全区和底部列表内边距单独计算，不让状态栏、TabBar挡住文字。
- 长名字、长地址、大字体、冷却、保护保留、无联系方式、无数据、加载错误与权限变化需在实现阶段验证；设计图不等于这些原生状态已通过验收。
- 使用 `ui-ux-pro-max` 检索设计系统与搜索/筛选、触控指导。采用匹配的扁平低装饰和触控建议；检索返回的营销布局、西文字体和蓝绿配色不适用，保留已确认的原项目风格。未将普通 Vue/Web 建议视作 UTS/UVue 的原生支持依据。

# 客户页 V2：概览、名单、详情

2026-11-12。设计评审稿，未修改 App 页面。承接 V1 已确认的白底、石墨字、品牌橙与紧凑列表；本稿所有数字、门店、联系人均为设计示例，不是开发或生产查询结果。

## 已确认与本轮建议

- 用户确认：新增合作是门店首次与公司有效成交，且首笔订单归属当前业务员；老客户换业务员不重算公司新客。
- 用户确认：复购沿用 BI 跨期口径，本期成交且本期开始前已有公司有效订单；本期新客连续购买两次不算该口径复购。
- 建议：客户 Tab 首屏改为客户概览。点击统计或管理入口进入名单，点门店进入详情；返回保留时间、筛选和滚动位置。
- 建议：保留“我的客户／合作客户／公海”三个视图。合作客户反映个人历史交易关系，公私海反映当前归属，两者可以重叠，数量不可相加。
- 建议：联系人单独统计，待关注只保留能直接带到具体客户的三个入口，不叠加趋势图、说明卡或重复首页的金额看板。

## 第一屏：客户概览

从上到下：客户标题 → 时间切换 → 客户统计 → 联系人 → 客户管理 → 待关注 → 原有五项底部导航。

### 时间与核心统计

默认“今日”，常驻“今日／本月／上月”；右侧日期进入日期选择，沿用首页的历史月份与本年入口。历史月份显示月份，本年显示年份，不能继续高亮今日。Asia/Shanghai 自然日和自然月；本月截至当前时刻，上月完整月。

浅灰卡片内紧凑两行两列，示例为“成交客户 5、新增合作 2、复购客户 3、复购率 60%”。每格点击进入相同员工范围、相同时间和相同口径的名单。复购率进入复购名单，顶部保留“3 / 5家”的分子分母。解释口径收在名单的说明入口，不铺满概览。

### 联系人

独立标题“联系人”，右侧“查看 >”。下面单行两列“新增联系人 6／新增企微 3”。点击分别查看新增联系人与主动新增企微关系；联系人列表显示所属门店，多店关系用选择器进入对应门店，不能把一个人复制成多个新增人头。查看入口默认展示本人当前有权查看的联系人，支持姓名、手机号查询的前提是服务端实现相应能力。

### 客户管理与待关注

“客户管理”右侧小字“当前”，下面三个并排紧凑入口“我的客户 36／合作客户 28／公海 128”。这是当前名单入口，不随上面的统计日期变化。

“待关注”三行，每行可点击：即将掉落 4、60天未购 6、联系待完善 9。均为当前可处理客户，最多显示数值和箭头，不展示规则段落。三个条件可重叠，不汇总成去重待办总数。

- 即将掉落：自己的私海门店，24小时内到期，排除保护暂缓/保留；复用服务端 DUE_SOON。已逾期是另一状态，不能冒充即将到期。
- 60天未购：自己当前私海、曾与公司合作、最近有效公司订单超过60天；沿用 CRM 活跃度口径，拜访不重置未购天数。
- 联系待完善：自己当前私海中，没有一个可用于联系的有效门店联系人；具体以已核实电话或官方确认且本人可用的企微关系判断。该统计是建议新增的服务端条件，不冒充当前已有字段，也不用于判定拜访有效性。

## 第二屏：客户名单

二级原生页面顶部返回和“客户列表”。常驻页签“我的客户／合作客户／公海”，搜索框、筛选和结果数，下方使用 V1 的细分隔线列表。该二级页使用返回导航，不重复底部根 TabBar。

| 视图 | 范围 | 每行辅助信息 | 操作 |
| --- | --- | --- | --- |
| 我的客户 | 当前归属本人的私海 | 本轮阶段、最近拜访、保护到期 | 点击详情后拜访、下单、编辑 |
| 合作客户 | 历史有有效订单归属本人的统一门店 | 上次向我下单日期、向我下单笔数、当前归属标签 | 点击与当前权限匹配的详情 |
| 公海 | 当前无私海归属且在本人授权地区的门店，包含掉落/释放及其他可见未认领门店 | 地址、经营状态、历史合作、冷却 | 认领；详情仅公开信息 |

合作客户行标注“我的私海／公海／已转交”，与公司合作状态、本轮保护阶段分别建模。图稿展示这个新视图，公海沿用 V1 的认领设计。历史合作关联本身不授予查询他人私海现状、私人联系人、修改或拜访的权限；已转交视图只展示获准的公开门店资料和本人历史订单事实。服务端不支持这种最小权限投影时，实施前补齐接口和授权。

统计卡和待关注进入“对应名单”而不是无筛选的全部客户：顶部固定展示期间及条件，可返回概览更换时间。不能先算全量数值，再只在当前20条列表里过滤。累计合作入口不被时间页签悄悄截断。

历史订货账户尚未全部关联统一门店，更多菜单保留原订货客户查询/购物草稿路径；不按同名自动合并，也不让未关联客户无声消失。新建门店遵循查重、准入、入公海与认领流程，后续补充完整交互，不加一个直建私海的快捷按钮。

## 第三屏：客户详情

顶部“客户详情”，有权限时右侧“编辑”。主体：店名、当前归属/阶段、完整地址、保护期限；两列紧凑交易摘要“累计成交／待回款”；随后“联系人／拜访／订单”内容页签。

- 联系人按真实门店关系展示姓名、角色、主要联系人、电话核实状态、官方企微状态。电话可呼叫，地址可导航，已有 App 对应能力复用；授权按使用时请求。新增、编辑联系人及多店关系沿用现有 CRM 规则，不把手填微信线索标成官方已建联。
- 拜访页签展示历史记录及状态；订单页签展示当前授权范围内的实际订单，详情按订单标识查找，不能继续按客户名称猜匹配。
- 底部固定“去拜访／下单”，按当前门店、归属、经营状态和订单权限显示可用动作。有进行中拜访时显示“继续拜访”，不另开重复拜访。公海以“认领”为主动作；认领成功才能进入当前归属允许的作业。
- 释放客户、经营状态修改等低频动作放在更多；编辑客户资料保持显式入口。已转交历史客户不展示本人无权使用的编辑/拜访动作。
- 累计成交、待回款与订单列表必须采用同一可见范围。本稿为本人归属订单示例，不暗示可以查看门店跨业务员全部欠款。交易统计与首页全款回款目标是不同口径。

## 指标定义与下钻合同

所有客户指标按公司统一 store_id 去重。订单归属采用交易时归属快照，不随今天的私海归属改变。有效订单沿用 CRM/订单域合同，排除草稿、取消、删除；退款/作废后的有效性与历史回算按同一后端合同处理，不能前端自创净额门槛。

| 指标 | 分子/定义 | 下钻 |
| --- | --- | --- |
| 成交客户 | 期间有有效订单归属本人的门店数 | 同期本人成交门店，附该范围订单 |
| 新增合作 | 门店首次公司有效成交在期间内，且该首笔订单归属本人 | 该组门店及首笔订单 |
| 复购客户 | 本期本人有效订单客户中，本期开始前已有公司有效订单的门店数 | 该组门店及本期本人订单 |
| 复购率 | 复购客户 / 成交客户 × 100%；分母0显示“—” | 同一复购名单与分子分母 |
| 新增联系人（建议口径） | 本人在期间新建且已规范去重的有效联系人，按 canonical contact_id 去重 | 新增联系人及当前可见门店关系 |
| 新增企微 | 员工与规范联系人首次 DIRECT 主动建联发生在期间内，来源可核验 | 员工与联系人关系及可见关联门店 |

新增联系人不将补电话、核实电话、给既有人增加第二家门店关联重复记新；历史导入时间不能当作真实新增时间。新增企微不把离职转接、删除后重加、同步入库时间算首次；未知真实日期单列待核对。当前手机号是否允许明文展示、呼叫和复制遵循既有权限。

跨期历史判断不能只查当前业务员的历史订单：先查公司历史，再限定本期本人归属订单。由于公司首单可能属于其他业务员，本期另一位业务员接到第二笔时，成交客户不一定等于新增合作加复购客户，界面不能画成强制相加的漏斗或堆叠图。本期复购率不平均每日百分比，按期间重算分子分母。

原 BI customer_id 不是统一门店 ID 的同义词。多订货账户、一账户多店、未关联历史先按已确认映射归一；未关联、首次时间未知、旧数据范围不完整需有待关联/待核对状态，不能猜为0或新客。沿用 BI 指标含义不等于直接使用其当前账户粒度返回值。

## 当前能力与待实现

- 已有可复用：公私海查询、认领、门店/联系人维护、拜访、部分服务端地区/保护/阶段/活跃度条件。
- 待补：概览聚合、个人合作历史视图、统计条件下钻、统一门店订单关联、联系人统计、官方企微数据接入与状态核验；不能逐行请求详情凑全量统计。
- 原生 commerce 当前下单链路仍有本地草稿限制。后端已有 StoreOrderSubmissionService，以订单权限、当前 ownership 和 CRM 授权提交；实施时接通并验收完整链路，不能把设计图中的“下单”称为已上线功能。
- 现有 BI 有小时刷新设计。实际复用缓存时应带更新时间或延迟状态；无数据与加载失败区分。无权限不展示错误的0，接口未接入显示“—”，不写入图稿示例数。
- 门店当前资料、历史订单与历史联系人授权分开验证；历史合作客户不可成为跨私海越权入口。

## 视觉、状态与验收

白 #FFFFFF、正文 #252A31、辅助 #626970、橙 #C64C1C、浅灰 #F5F6F7、边界 #D6DBDF。手机左右20px，标题23/32，店名16/24，辅助13/20；数据用对齐数字。紧凑行约48–56px，触控区不少于48dp。不得为了塞一屏缩成小字。需要时页面自然纵向滚动；安全区、固定操作栏和列表内边距独立计算。

只有概览保留根底部导航，客户高亮；拜访使用定位图钉，订单使用剪贴板。二级名单使用返回，详情使用返回加底部作业按钮。公海认领仍需确认门店与首访要求，错误/竞争认领以服务端返回为准。

开发验收应覆盖：今日/月份/年份切换及分母0；同店多账户和未知历史；新客当期买两次；跨业务员订单；客户转交后指标不漂移但权限改变；统计数和下钻全量一致；联系人多店关系及企微转接重加；保护暂缓、冷却、无权限、无数据与接口失败；小屏和大字体；返回保留条件；真实拜访与正式下单。这些均为后续实现验收，不宣称本次设计已通过。

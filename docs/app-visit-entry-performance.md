# 门店拜访入口与统一规则缓存

2026-11-13 实现，2026-11-16 补充到店重定位交互与真机验收。正式实现方案与本地验证记录，非生产发布声明。

## 问题与行为

原入口点击后先后查询考勤、规则、门店、历史和工作日，再等待最长 12 秒的高精度定位；按钮文字未变化，错误可能出现在滚动内容下方。用户要求按正式上线的作业链路修复，规则、缓存和数据归属统一设计，不做仅适配当前测试门店的分支。

- 门店详情读取成功后，在后台准备适用规则和距离；拜访入口与弹窗不展示距离、允许范围数值，也不在按钮上方重复堆叠错误提示。附近客户列表仍按原需求展示距离。
- 点击同步锁定动作，显示准备拜访／获取位置／更新位置／检查上班状态／核对拜访／正在进入等实际阶段，直至导航成功或错误对话框关闭；图标和文字区域共用同一个防重入口。
- 有效的近期定位直接复用；已知超出规则范围时，在签到、麦克风申请和创建拜访之前提示“请到店后再开始拜访”。左侧“我已到店”强制重新获取定位并核验，右侧“知道了”关闭。
- 首次尝试没有可用定位才补采集；主动点击“我已到店”即使有近期结果也重新定位，继续共用原动作锁。符合范围后继续原拜访流程，仍不符合则再次显示同一简洁提示；定位失败单独提示实际错误，不当作超范围。使用既有位置服务的 3 秒高精度等待参数；网络标准化仍有实际网络耗时，不能宣称整个流程保证 3 秒完成。
- 已有进行中拜访走原会话恢复，由现场页读取该次拜访的规则快照，不因新发布规则重新要求打卡或阻断旧会话。
- 离页、账号变化会使尚未提交的动作失效。实际创建继续使用已有持久化请求号和服务端幂等协议，不用按钮禁用替代后端校验。

## 端到端职责与缓存合同

| 数据 | 归属与复用位置 | 更新、一致性和边界 |
| --- | --- | --- |
| 当前适用规则 | Sales 发布；App `services/visit-policy.uts` 单一内存缓存 | 登录、会话恢复和回到前台预加载；前台每 60 秒刷新，缓存读取上限 5 分钟；合并在途请求。所有页面共用，页面不另设 TTL。加载失败清除当前快照，由交互入口给出错误 |
| 已有拜访采集规则 | Sales 按 capture ID 关联规则版本；同一 App 服务复用 | 最多 20 个会话、每个 10 分钟；保持原版本，不跟随新规则覆盖 |
| 规则版本内容 | Sales 复用后端 `shared-cache.QueryCache`、服务内 Redis 适配器 | `visit-policy-definition` / `visit-policy-snapshot` 按租户、调用方授权上下文和版本 UUID 隔离，TTL 上限 24 小时；发布产生新 UUID。受单条大小、租户容量、加载并发、合并请求与 Redis 故障回源约束 |
| 人员适用版本 | Sales 当前身份 + `sales_policy_scope` / `sales_team_member` / 版本有效期 | 仍即时选择版本 ID，避免调组、范围变化和定时生效因缓存滞后而错误放行；随后从缓存获取完整规则内容。不能宣称规则 API 完全不查数据库 |
| 门店、归属和正式拜访 | CRM | 位置和规则预检仅用于及时反馈；服务端仍核对最新归属、工作日、范围和幂等状态。CRM 通过 Sales API 获取规则，未增加另一套独立规则库或缓存 |
| 当前位置 | 既有 `location.uts` → CRM 标准化 → `customer-nearby.uts` | 名单与详情复用账户隔离的近期结果；提交准备点另检查 30 秒请求年龄、正数精度、账号和坐标。过期/低精度/未知来源不能作为拜访定位 |

App 缓存随环境、接口地址、租户、账号、会话修订及权限变化清理，旧请求回包不能填入新会话。退出前台暂停规则轮询。没有把规则写入长期本地存储，也没有为当前测试设置固定范围。

服务端权限检查发生在进入缓存读取之前；未授权内部调用不使用该授权缓存。写事务绕过内容缓存，避免发布过程尚未提交的版本或采集快照污染共享缓存。普通规则查询可命中 Redis；事务性写入仍保留必要的数据库读。

版本内容缓存使用现有 `sales_visit_policy_version`，没有新建业务表或修改历史迁移。适用版本选择保留原 SQL 的身份、范围、有效期条件，只选择 ID；内容按版本读取。现有版本有效期索引、范围索引和主键继续使用。本批没有针对该选择 SQL 宣称新的生产执行计划或大规模压测结果。

## 位置与错误处理

原生采集 WGS84，与门店 GCJ02 分开计算；使用既有标准化接口返回的两套坐标，不仅改标签。提交复用 GCJ02 和真实精度，保持现有后端合同。

`requestedAt` / `receivedAt` 是定位请求和回调时间，不冒充设备实际采样时间。展示距离可能来自较旧的列表快照；开始拜访另行检查 30 秒年龄。客户端距离拒绝留 1 米保守余量，最终范围仍由服务端判定。客户端缓存更新前若后台刚发布新规则，服务器可能返回新规则校验结果，页面会明确显示该错误。

独立的归属、详情、历史读取在 `crmStartVisit` 中并行；身份和工作日等有依赖的检查仍按顺序执行。未知网络失败保留原请求号以便幂等恢复；服务端明确未创建的超范围或精度不足错误才清除旧命令，允许重新定位重试。

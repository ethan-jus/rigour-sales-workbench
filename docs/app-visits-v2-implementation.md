# 拜访页 V2：上下班打卡与首页状态

2026-11-13。在原项目实现，未发布生产。本次用户确认的 V3 圆形打卡设计覆盖 V1 的记录优先布局及首页签到入口。最新追加要求：首页「工作中」使用打卡橙色，表情呈现奋斗状态。

## 页面和业务行为

- 首页右上角仅展示「未上班／工作中／已下班」与定制透明表情，不提供签到、签退或下拉面板。工作中使用 `#c64c1c`，与打卡按钮一致；橙色头带表现积极工作。未知、失败、待同步状态不冒充已确认工作状态。
- 拜访根页展示日期、真实上下班状态、圆形打卡、今日拜访与计划；不放表情。未上班执行上班打卡；工作中执行下班打卡，须确认；成功回执后切换状态。进行中的拜访或录音阻止下班，保留继续拜访入口。
- 完成态采用浅薄荷绿 `#e2f5e9`，圆内只有完成勾与提示。工作时长位于「已下班」右侧，读取 Sales `verifiedWorkMinutes` 累计值，不能用首次签到与末次签退相减替代多工作时段累计。
- 右上角历史进入独立「拜访记录」页，保留期间、搜索、状态筛选、统计和分页。首页有效／新增等统计下钻直接带日期与类别进入历史页。
- 计划保留真实状态、日期选择、原有 CRM 授权选择流程；签退不会将待拜访计划自动变成已完成。已完成且无关联记录的计划不会误发起新拜访。
- 继续复用现有定位、加密待同步命令、幂等与后台轨迹服务；未改后端业务规则或生产数据。

## 文件

- `app/pages/visits/visits.uvue`：打卡、当前拜访、计划。
- `app/pages/visit-history/visit-history.uvue`：原记录查询功能迁入；已注册到 `app/pages.json`。
- `app/pages/home/home.uvue`：只读状态、表情与颜色。
- `app/services/visit-workbench.uts`：历史页和计划页导航；不改变查询合同。
- `app/static/home/status-{ready,working,finished}.png`：内置 Image Gen 生成的三个透明素材，约 28px 视觉大小；未使用系统 emoji。
- `scripts/test-app-visits-page.cjs`：实际页面脚本的打卡、权限、账号隔离、计划场景测试。

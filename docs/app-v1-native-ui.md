# 销售工作台 App V1 页面实施记录

更新日期：2026-10-14。本文记录本地源码实现及其验收边界，不代表生产部署、业务接入或三端真机验收完成。

## 本轮页面与接入范围

正式原生工程位于本仓库 `app/`，版本 0.2.0，沿用既有 DCloud AppID。按确认的暖白/橙色设计实现工作台、客户、拜访、订单、我的五个主 Tab，并提供公司登录、客户详情、商品列表/详情、购物草稿、确认信息、订单详情、回款/退货入口、目标业绩、提成、消息、账号设置和定位录音检查等子页面。

- 工作台展示真实可取得的本人拜访统计、本机未完成草稿与常用入口。未接通的订单业绩/到账金额使用“—”与待接入文案，不灌入设计示例数字。
- 商务页使用核对后的只读 CRM/ERP/Order 合同；按平台授权范围命名“客户/订单”，不假定宽权限账号只能看本人。商品仅取默认参考销售价，不取进价和未授权规格详情。
- 购物草稿按租户、稳定用户 ID 和客户分别保存，增减/删除/地址编辑遇到存储失败回滚，不展示保存成功。当前没有正式报价与订单提交，也不调用会直接记账的管理收款接口。
- 拜访照片与录音复用 G0 原生能力；页面保留本机材料，正式 200 米核验、地图、上传及服务端确认尚未就绪。
- Android 的系统浏览器 OAuth Code + PKCE 为真实协议接入骨架，配置默认留空；没有注册移动客户端及真实 IAM 联调就不能登录。iOS/鸿蒙登录明确尚未启用。令牌仅内存，不写普通存储。
- 五个 Tab 在未登录时可浏览页面结构；账号、客户、订单、拜访等真实业务数据均需平台登录和权限。权限拒绝、空记录、网络失败分别展示。

接口与缺口见 [app-v1-api-readiness.md](app-v1-api-readiness.md)，登录接入见 [app-v1-auth-integration.md](app-v1-auth-integration.md)。本轮没有更改 Platform、临时打卡服务或生产配置。

## 拜访页面

沿用已批准的暖白底色、橙色操作按钮和五个主导航方向。拜访页面使用原生 `scroll-view direction="vertical"`，不依赖浏览器滚动或设计原型中的模拟状态。

源码：

- `app/pages/visits/visits.uvue`：本人正式记录与本机草稿列表。
- `app/pages/visit/visit.uvue`：`view=select/active/evidence/detail/uploads/plan`。
- `app/services/visits.uts`：只读接口、草稿持久化、照片文件引用、定位和录音会话。

| 页面或流程 | 当前实现 | 尚未接通的部分 |
| --- | --- | --- |
| 我的拜访 | 使用正式本人记录接口；按北京时间单日查询、清空日期查全部、20 条分页；独立展示本机草稿 | 正式列表合同不支持日期区间；不把本地草稿计入已提交记录 |
| 选择门店 | 查询本人有效负责门店；输入后 350 毫秒查询内部档案；点击搜索先请求原生定位；无高德请求 | 无统一坐标系合同，不能声称按距离排序；当前按接口门店名称排序 |
| 现场沟通 | 沟通对象和记录即时保存到本机；服务层持有原生录音会话；可暂停、继续、停止保存并回放 | 复用 G0 的停止后持久保存能力，未升级为录制中分段持久化 |
| 现场照片 | 调用真实相机或相册；照片复制到应用沙盒后才加入草稿；最多 9 张；缩略图、预览、移除 | 无正式上传、服务端收件确认；移除仅从草稿取消关联，不清理沙盒孤立文件 |
| 本机材料 | 展示每份草稿的照片和已保存录音，并可继续编辑 | 明确显示“未提交/未上传”，没有模拟上传成功或假进度 |
| 正式拜访详情 | 请求详情中的目标快照及服务端 checkpoint 距离；独立查询照片和录音元数据 | 现有 DTO 没有媒体访问 URL，不渲染假缩略图或假播放器；地址写“地址待解析”，地图尚未接入 |
| 拜访计划 | 使用当前日期的本人计划接口；已有 visitId 可进入真实详情 | 不生成设计原型中的示例计划，不在客户端创建签到事实 |

所有请求通过共享 `requestApi`，使用 `/sales/...` 相对路径，由共享层拼接 `/api/v1`、附加当前会话并处理失败。Sales 成功响应从根对象的 `data` 解包。登录缺失、权限不足和接口失败均显示明确状态，不回落到演示记录。

## 本机草稿与录音的状态边界

1. 草稿按租户与稳定 IAM userId 分别存储；账号更名不会丢失关联，同名新账号不会继承旧草稿。没有真实登录和 `sales:visit:own:write` 权限，不能创建拜访草稿。
2. 草稿只存照片相对文件名、录音索引和业务文本，不把照片或音频转成 Base64，不保存访问 Token。照片与录音路径在运行时根据当前应用沙盒还原。
3. `services/visits.uts` 持有录音会话。普通业务页面的隐藏或卸载只停止回放，不调用录音的 `dispose`，避免跨页主动中断。
4. 正在录音、暂停或保存期间禁止创建另一份拜访。停止后收到持久文件与索引，才将录音关联到启动时的草稿；重复保存回调不重复添加同一录音。
5. 账号失效或切换时，会话监听器要求停止旧录音。即使保存回调发生在新账号登录后，仍按录音启动时的账号和草稿编号写回原账号，不把材料挂到新账号。
6. 选店页定位只更新用于新草稿的位置，不覆盖上一份草稿。草稿主动刷新定位时，回调绑定发起时的草稿编号，避免跨页回来后改错记录。
7. 保存失败时保留内存内容，在页面顶部明确显示“草稿尚未保存到本机”及重试按钮，不能保证应用强制关闭后的恢复。若录音文件已保存但草稿关联失败，提示保留本机文件，并可从已有设备检查页核验原文件。

拜访内部导航按 route、view、id 精确查找现有页面并返回，避免“沟通→照片→材料→继续编辑”反复堆叠；不同草稿或不同记录不会误复用。

正式写入保持阻断：现有定位提供 WGS84，但门店接口未声明坐标系，也没有独立采样时间和地址合同；因此没有把粗略客户端距离当成 200 米核验结果。当前没有自动创建工作日、发起正式打卡或偷偷绕过签到前置。`recording/saved` 只说明已收到原生 API 回调，不代表持续后台录音、音频完整性或上传已被验收。

## 拜访专项验证

可复跑命令（仓库依赖已安装时）：

```bash
node scripts/test-app-v1-visits.cjs
```

测试依赖项目的 `typescript` 和 `vue/compiler-sfc`。若只安装了 HBuilderX、没有仓库 `node_modules`，可通过 `NODE_PATH` 指向本机 HBuilderX 对应 Node 模块目录；测试脚本本身不依赖临时目录或机器固定路径。2026-10-14 本机执行时使用了 HBuilderX 的 TypeScript 和 Vue 编译器模块，13 项通过。

13 项由 **2 项语法检查与 11 项行为测试**组成：

- 两个 `.uvue` 文件的 SFC、模板表达式与 TypeScript 兼容语法检查。
- 草稿文本经存储后，在新服务实例中恢复。
- 无登录或无写权限时，不创建草稿。
- 选店定位不改旧草稿；延迟定位回调只更新原发起草稿。
- 单一录音会话、暂停/继续/停止状态、保存前禁止创建另一拜访、重复回调去重。
- 账号失效时停止旧录音；另一账号登录后的延迟保存仍归属原账号。
- 照片复制成功前不添加草稿材料；复制成功后只存相对文件名，移除后取消关联。
- 本机存储失败返回失败，同时保留当前内存草稿。
- 只读 API 的权限阻断及有效 `data` 包装校验。
- 稳定 userId 在账号更名后保留关联，同名不同 userId 隔离。
- 新建草稿首次保存失败时仍可编辑，并明确标记未保存；重试成功后恢复保存状态。
- 执行页面真实导航函数，验证精确 view/id 返回、其他草稿新开与当前页重复点击不堆栈。

行为测试执行真实的 `visits.uts` 服务函数，经 TypeScript 转译后替换 `uni` 存储、原生录音/定位回调和 Vue 账号变化投递。它们不是静态源码字符串断言；但文件存储是内存 Map、原生回调是模拟回调，所以不能证明 Android/iOS/HarmonyOS 的文件实际落盘、麦克风持续采集、后台长录音或系统中断恢复。

仍需独立验证：UTS 三端编译；已登录真实账号的接口数据与权限；相机/相册授权；重启 App 后图片和录音回放；切换业务页录音；锁屏/切换应用/电话中断；长录音完整性；低空间与进程强制退出；200 米正式核验及上传服务端确认。统一编译和后续真机记录由主任务追加，不能由本专项测试替代。

## 已落地的页面

- 客户根 Tab 改为概览；默认今日，支持本月、上月、本年和历史月份。统计与名单传递同一日期及条件。
- 概览包括成交、新增合作、复购、复购率，联系人，当前我的客户／合作客户／公海，以及即将掉落／60天未购／联系待完善。
- 客户名单为原生二级页，支持服务器搜索、分页、保护阶段及归属筛选。返回刷新数据并保留搜索条件，公海使用既有带版本号、幂等键的认领接口。
- 客户详情展示资料、归属、订单金额、联系人、拜访、订单；支持资料编辑、经营状态、释放客户、联系人新增／关联／维护／核实，以及既有拜访和订货入口。
- 暂停营业／停业客户禁用新拜访和选购；仍可继续已有拜访。历史合作只开放最小门店信息和本人历史订单，不开放他人当前私海联系人及编辑动作。
- 一人多店按联系人去重，展开选择本人当前有权限的门店。手填微信线索不当作官方企微关系。
- 原 `pages/crm` 保留为维护表单，原 CRM 列表及详情入口重定向到新页面；旧订货账户查询移动至 `pages/ordering-customers`，从概览更多菜单进入，避免未关联历史账户消失。

主要原生文件：`app/pages/customers`、`customer-list`、`customer-detail`、`customer-contacts`、`app/services/customer-workbench.uts`、`app/styles/customers.css`。

## 后端与统计口径

新增只读 API（通过既有 Gateway 调用）：

- CRM `/api/v1/crm/customer-workbench/overview`：聚合统计。
- CRM `/api/v1/crm/customer-workbench`：合作历史及指标名单。
- CRM `/api/v1/crm/customer-workbench/contacts`：联系人统计名单及当前授权门店关系。
- CRM `/api/v1/crm/customer-workbench/{id}/orders`：本人历史交易事实及历史视图授权。
- Order `/api/v1/orders/customers/{id}`：统一门店下本人可见的正式订单、金额与待回款，支持待回款过滤与分页。

复用 CRM 本地订单事实、门店汇总及当前权限，按 `store_id` 去重；不存在跨服务直接查询数据库。新增合作要求公司首笔有效订单归属本人，复购检查公司跨期历史；本期新客买两次不算复购。取消／无效订单不计入。日期按 Asia/Shanghai；0分母或存在待核对历史时复购率显示“—”。所有租户／员工／地区约束由服务端验证。

交易范围目前仅包含已正式关联统一门店的订单，界面“统计范围”说明这一点；不通过名称猜测账户映射。联系人新增按本人 CREATE 审计事件、规范联系人ID去重，且仅展示当前仍有权限查看的有效关联。新增企微暂无官方来源，显示“—”。

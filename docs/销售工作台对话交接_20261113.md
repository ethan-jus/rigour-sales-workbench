- 启动恢复会话，有效进入首页、无效进入登录；已删除多余作业准备页，不要再加回来。定位/麦克风在相关功能使用时请求，不在首页统一拦截。

### 3.2 首页

- 默认“今日”，常用今日/本月/上月；点击日期选本年及历史月份。中国业务时区 Asia/Shanghai，不允许未来月份。
- 交易额与笔数同行；累计待回款显示金额和笔数，点击进入对应明细。累计待回款、待出库、今日待拜访不随统计期间漂移。
- **业绩按整单全款付清口径，不是任意到账金额累计**。今日/本月展示本月目标；上月/历史月取对应月；本年累计 1 月至当前月指标。回款与总指标放进度条两端，保持紧凑。
- “拜访与建联”标题必须保留，不能与订单业绩混成一块；两行展示“拜访/有效/新增/企微”，名称与数字同行。企微官方关系未接入时显示“—”，不能用普通联系人或手填微信冒充。
- 常用操作：开始/继续拜访、查客户、查商品、拜访计划。图标和按钮需对照确认稿。
- 当前待办：待回款、待出库、今日待拜访，点击新明细页面，不在首页展开；最新约 53px 行高（含分隔线），不能再叠加大内边距。
- 查询首页不自动签到；需处理进行中拜访和本机草稿。详细业绩计算、退款/归属待核定等见 [首页实施记录](app-home-v5-implementation.md)。

### 3.3 客户

- 客户根 Tab 为经营概览，再进入名单，再到客户详情。详情承接拜访、下单、修改资料、联系人等操作。
- 我的客户＝当前私海；公海＝当前授权地区内、未被他人私海占有的可见客户；合作客户＝与本人有历史有效交易的门店，不能因此开放他人现有私海联系人或编辑权。
- 时间切换与首页一致；新增合作按**公司首次有效成交且该首单归属本人**。老店换业务员不算公司新客。
- 复购沿用跨期口径：本期再次下单的老客户 / 本期成交客户，老客在本期开始前已有成交；本期新客买两次不计这个口径的复购。分母为 0 或历史待核对时显示“—”。
- 客户按 CRM `store_id` 去重；联系人一人多店不重复算人；官方企微关系单独处理。
- 公海列表、总数、概览、分页必须同一授权范围；省/市/区县层级明确，地址补齐地区。认领为橙色细边框 72×32 视觉尺寸，外层 80×48 点击区；底部拜访为带勾夹板图标。
- 历史订单未可靠映射统一门店时，首页有交易但客户成交统计为 0 可能是关联覆盖差异，不能为凑数字按名称自动关联。
- 暂停营业/停业禁用新拜访及选购，已有拜访可继续；历史合作只开放最小必要信息。

### 3.4 拜访与交易边界

- 拜访根页：记录/计划、期间、拜访/有效/新增、搜索筛选分页、真实状态、时间时长和历史地址；现场页沿用紧凑录音条、照片、接待人、结果、意向和完成入口。
- App 拜访工作台查询入口归 Sales：App → Sales `/api/v1/sales/me/visit-workbench` → CRM `/api/v1/crm/store-visits/me`。CRM 保存正式拜访事实与最终有效性，Sales 不重复保存可独立修改的正式事实。
- 现场完成先保存结果再离店；Sales 离店不能直接当 CRM EFFECTIVE。正式门店与旧计划 UUID 尚缺可靠关联时，进入客户选择，不按名字自动匹配或伪造计划完成。
- 订单/报价/回款/退货未开放部分要如实展示，不能把购物草稿当已提交订单。详细限制见对应文档。

## 4. 外勤风控总目标与职责

用户关注：上下班时间与位置、每日工作轨迹和距离、异常/非惯用设备与代打卡线索、录音与公司业务关联、有效拜访、反复去同一门店凑次数、过密复访、上下班是否长期出现在同一常用地点。后台需从销售某一天进入地图、距离、时间线和原始证据。

- 签到签退记录工作时间边界；轨迹必须另有会话采集，不能靠两个打卡点假装整日轨迹。
- 门头照片只能现场拍照，录音只能 App 内采集，不允许相册/文件导入；服务端也校验来源。仅限制入口不能保证证据绝对真实。
- 音频可异步转写、时间片段回听和摘要；AI 是复核线索，保留原音频，不自动据此判作弊或改 KPI。转写失败不阻塞签退。
- 未确认地点不能直接称“家”；安装 ID 不能证明设备可信。技术采集缺失与真实作业异常区分。
- Sales：工作日、签到签退段、采集会话、原始材料与轨迹、技术校验、日监督、说明/人工核查及审计。
- CRM：门店/联系人主档、归属、正式拜访及最终有效性；Order：交易；IAM/HR：身份/组织/授权；外部 ASR/地图通过现有适配边界接入。
- 原始 WGS84 证据与标准化 GCJ02 分开保存，不只改坐标标签、不混算距离；缺口不连假直线、不可计算距离不伪装成 0。
